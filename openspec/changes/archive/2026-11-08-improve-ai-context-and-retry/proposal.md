# Proposal

## Why

AI 回复只看最近 30 条消息，超出窗口的话题完全记不住；滑动窗口让提示词开头每轮都变，服务商的前缀缓存几乎命中不了；真实模型常模仿历史格式，在回复开头写上“自己名字：”；所有服务商错误都按同一种退避重试，内容审核拒绝也会白白重试；上下文按字符计，中英文的实际 token 费用相差数倍。

## What Changes

- **回复清洗**：可选去掉回复开头的“自己显示名 + 冒号”，流式草稿和正式消息一致。
- **前缀缓存友好窗口**：可选让历史窗口起点按块对齐，超预算时按块丢弃；Claude 请求给 system 和稳定历史加缓存标记。
- **检索增强上下文（轻量 RAG）**：可选复用 V10 的 ngram 全文索引，在本房间窗口之前的消息里检索相关记录，作为标明“仅供参考”的一段放在最新一条消息之前；失败或超时跳过。
- **按错误类型重试**：可选把服务商错误分为限流/过载、上下文过长、内容拒绝和其他，分别退避、减半上下文重试一次、直接失败、按原规则重试。
- **token 预算**：可选按估算 token 而不是字符限制历史。

所有开关默认关闭，关闭时行为与现在一致。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `ai-replies`：增加可选的回复清洗、缓存友好窗口、检索参考、分类重试和 token 预算。

## Impact

- 只改 Python AI 服务（`ai/chat_ai`）、compose 环境变量、`.env.example` 和 README。
- 不改 gRPC、C++、数据库结构、迁移和数据库账号权限；检索使用 AI 账号已有的 `messages` 只读权限。
- 计费归属、权限复核、停止/暂停语义、失败持久化不变。
