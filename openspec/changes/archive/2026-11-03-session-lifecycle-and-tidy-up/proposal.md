# Proposal

## Why

会话只在建立 WebSocket 连接和发送消息时校验。登出或会话过期之后，已经打开的页面仍能继续收到房间里的消息，这与“登出后会话立即失效”的本意不符。另外，会话固定 7 天过期，常用设备上的用户也会被定期踢出登录。前几个阶段还留下了几处小的遗留：已弃用的 SQL 写法、已弃用的 CI action，以及开发库里大量的测试数据。

## What Changes

- **会话结束时断开连接**：
  - 登出：立即断开被结束的会话的 WebSocket 连接，包括其他聊天服务实例上的。从受信任设备登出时，结束该用户的所有会话、断开所有设备；从其他设备登出只结束当前会话。
  - 会话过期：由聊天服务自己的定时器定期批量检查，在检查间隔内断开（默认 30 秒，可配置）。
  - 这种断开带有专门的关闭码，前端收到后不再自动重连，直接回到登录页。
- **受信任设备**：每个用户最多一台受信任的手机和一台受信任的电脑（按 User-Agent 判断，平板算手机）。某类的第一台设备登录后直接受信任；之后另一台同类设备最近 30 天发的消息超过原设备的 1.5 倍时，在它登录或续期时替换原设备。
- **受信任设备自动续期会话**：新增 `POST /api/auth/refresh`。当前会话所在设备受信任时，把会话的有效期重新延长到完整时长；会话令牌不变，已建立的连接不受影响。其他设备拒绝续期。前端登录后定期调用（默认每 6 小时）。
- **测试数据清理脚本**：按用户名规则清理集成测试留下的账号、房间和消息。默认只预演并打印数量，加 `--apply` 才执行，在一个事务里完成。默认只匹配集成测试的用户名，其他前缀用参数加入。
- **小的遗留**：
  - `ai/chat_ai/keys.py` 的 `VALUES()` 改为 MySQL 8 的别名写法。
  - CI 的 `actions/checkout` 从 `@v4` 升到 `@v5`。

不在本次范围内：验证 GPT、Claude、Gemini 的模型名；“这台设备上的所有会话”之类的会话管理界面；第 1 堆的上线准备（HTTPS、备份、审核等）。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `realtime-messaging`：新增“会话结束时断开连接”。
- `user-auth`：修改“用户登出”（受信任设备登出结束全部会话）；新增“受信任设备”“受信任设备续期会话”。

## Impact

- C++：`SessionStore` 增加续期；新增一个按实例记录全部 WebSocket 连接及其会话的注册表和检查定时器；登出时通过 Redis 广播被撤销的会话；`AuthController` 新增 `refresh`。
- 前端：`ChatSocket` 识别会话结束的关闭码，不重连并回到登录页；登录后定时调用续期。
- 测试数据清理脚本（`tests/integration/cleanup_test_data.py`，在测试容器里运行），并在 README 说明用法。
- 配置：`.env` 新增会话检查间隔。
- Python：`keys.py` 的 SQL 写法。CI：`checkout` 版本。
