# Design

## Context

main已包含请求暂存、事务幂等、离线重试及故障恢复。Vue已有历史分页和AI补全，Python按房间持久保存生成任务。

## Goals / Non-Goals

实现已确认的四项能力并复用现有协议。后续分支直接基于已合并PR12的main。

## Decisions

阅读位置与入群基线保存在room_members，更新与消息提交共用房间行锁。SQL统计排除自己的消息，人的提及在消息保存时确定目标并保存关联，历史仍可回看。分页搜索绑定参数并限制返回量，定位共用历史接口。

AI控制以MySQL房间控制和生成记录为持久化边界。生成记录关联payer、generation_id、当前尝试快照及结束状态。停止与消息提交按房间行锁串行，已保存结果优先，停止部分内容按原generation_id落库。Python在领取、分片及心跳时检查控制并取消上游，最终提交检查数据库状态。暂停保存消息位置截止线，恢复只接受其后新触发。消息及协议携带stopped状态，停止部分不触发接话。

日志沿用Drogon入口，关联业务请求编号与每次处理，JSON字段白名单。可测阶段记录单调耗时，容器日志配置轮转。新增业务路由接入RequestBuffer分派，排队受理与实际控制成功分开显示。

## Risks / Trade-offs

SQL控制快照增加写入，按现有分片节奏合并并在测试中记录。跨设备已读采用服务端位置收敛。所有数据库变更新增迁移，不编辑旧迁移。使用隔离Compose项目运行回归，保留原故障断言。

## Migration Plan

新增V6迁移、AI新表最小权限、协议一起构建，再启动服务。旧room_members回填当前last_seq避免升级后历史全算未读。先数据库迁移后应用，回滚应用保留新增列与表。
