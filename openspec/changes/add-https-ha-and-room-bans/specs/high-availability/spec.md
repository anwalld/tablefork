# Spec Delta

## Purpose

保证系统以多个聊天服务实例和多个接入实例运行时，行为与单实例一致；任一实例或 Redis 主节点故障时，服务能在不重启其他组件的情况下继续工作。

## ADDED Requirements

### Requirement: 聊天服务多实例
系统 SHALL 以多个聊天服务实例运行，任一实例 MUST 能处理任何用户的任何请求和实时连接。用户的会话、房间状态和消息顺序 MUST 与请求落在哪个实例无关。

#### Scenario: 会话在其他实例上有效
- **WHEN** 用户在一个实例上登录，随后的请求落到另一个实例
- **THEN** 该请求按已登录处理

#### Scenario: 跨实例推送
- **WHEN** 成员甲的连接在实例 A 上订阅了房间，成员乙通过实例 B 发送消息
- **THEN** 甲在实例 A 上收到这条消息，且房间内消息序号连续

#### Scenario: 跨实例断开会话
- **WHEN** 用户的实时连接在实例 A 上，用户通过实例 B 登出
- **THEN** 实例 A 上的连接按“会话结束时断开连接”的规则断开

#### Scenario: 跨实例移出房间
- **WHEN** 被移出房间的成员的连接在实例 A 上，移出操作经实例 B 完成
- **THEN** 实例 A 上的连接立即收到 `room_left`，不再收到该房间的推送

### Requirement: 聊天服务实例故障
一个聊天服务实例停止时，系统 SHALL 把新的请求和连接交给其他实例处理。该实例上已有的实时连接会断开，客户端 MUST 能重新连接到其他实例，并按“客户端补齐”的规则补齐断开期间的消息。

#### Scenario: 实例停止后的新请求
- **WHEN** 一个聊天服务实例停止后，用户发出请求
- **THEN** 请求由其他实例正常处理，用户不需要重新登录

#### Scenario: 实例停止后重连
- **WHEN** 用户的实时连接所在实例停止
- **THEN** 客户端重新连接成功，并补齐断开期间房间里的消息

### Requirement: 接入实例故障
系统 SHALL 以多个处理 HTTPS 的接入实例运行。其中一个停止时，新的连接 MUST 由其他接入实例处理。

#### Scenario: 一个接入实例停止
- **WHEN** 一个处理 HTTPS 的接入实例停止后，客户端建立新连接
- **THEN** 连接由其他接入实例处理，请求正常完成

### Requirement: Redis 主节点故障自动切换
Redis 主节点故障时，系统 SHALL 在 30 秒内自动把从节点提升为新的主节点，聊天服务和 AI 服务 MUST 不需要重启就能继续读写。切换期间请求 SHALL 返回可重试的错误，而不是挂起。已经确认保存的聊天消息 MUST NOT 因切换而丢失。

#### Scenario: 主节点停止
- **WHEN** Redis 主节点停止
- **THEN** 30 秒内，登录、发送消息、实时推送和 AI 回复都恢复正常，且没有重启任何服务

#### Scenario: 切换期间的请求
- **WHEN** 切换尚未完成时，用户发送消息或登录
- **THEN** 系统在超时时间内返回可重试的错误，或者正常完成

#### Scenario: 已确认的消息
- **WHEN** 切换前已收到确认的消息
- **THEN** 切换后仍能通过历史查询读到

#### Scenario: 切换后断开会话
- **WHEN** 切换完成后，用户在一台设备上登出
- **THEN** 其他实例上属于该会话的连接仍按“会话结束时断开连接”的规则断开

#### Scenario: 原主节点恢复
- **WHEN** 原主节点重新启动
- **THEN** 它作为从节点加入，不会再接收写入，系统继续使用新的主节点
