# Design

## Context

现有SQL生成记录以`generating/final/stopped/saved`混合表达处理阶段和结束结果，并有独立`stopped`布尔值。Python失败处理清空快照，恢复逻辑读取同一记录；C++保存正式消息时将其置为saved。历史与热缓存没有失败消息元数据。控制检查同时发生在Python周期任务、片段处理和C++推送路径，搜索使用LOCATE。动机和范围见[提案](proposal.md)。

## Goals / Non-Goals

**Goals**

统一生成结果的保存和恢复边界，支持可见失败历史，降低停止状态重复读取，优化可索引搜索，补充Redis断连回归证据。

**Non-Goals**

范围限定于当前聊天室的生成、控制、搜索和恢复链路。业务权限、触发者付款、人设快照、入群隔离和现有恢复时限均作为兼容约束。

## Decisions

### 1. 分离处理阶段和结束结果

建议使用两类语义字段。

- 处理阶段为`generating`、`ready`、`finished`，分别表示生成中、已有待保存结果、结果已处理。
- 结束结果为`completed`、`failed`、`stopped`、`cancelled`和`legacy_unknown`。生成中尚无结束结果。

处理阶段决定恢复与重投，结束结果决定展示、上下文及接话规则。原状态中的stopped迁移为待保存的停止结果；已存停止消息由消息记录和原标志识别。旧saved记录缺少明确证据时标记legacy_unknown，保留其终态。兼容层由结束结果派生现有对外stopped标记。迁移在协调停写窗口按V8扩展与旧数据映射、调用方切换与约束核验、V9旧列收缩执行。新版本读取映射后的旧记录。旧C++和Python写入者须在迁移前全部停止，匹配新应用在收缩后开放。

单纯新增failed枚举无法解决saved阶段丢失结束原因的问题，因此采用阶段与结果分离。字段名称及迁移版本在实现时按现有迁移序列确定。

### 2. 失败快照与唯一历史

同一generation_id保留当前尝试快照，以及最近一次非空快照和它的attempt。新尝试开始时只清当前快照，最近非空快照继续保留。新尝试产生非空内容后原子替换候选，过期owner或较旧attempt不能覆盖它。候选始终属于同一角色、入群编号和逻辑生成，存储上限沿用消息内容限制。

最终失败先持久化待保存结果及选定快照。通过结果消息向聊天服务投递，聊天服务锁定房间与生成记录，校验成员、入群、尝试及控制状态，在同一事务保存消息和处理终态。失败重投恢复原消息编号。正常结果、停止结果、失败与移出取消并发时由这一持久化边界裁决，已处理终态不可被迟到写入覆盖。

所有尝试无内容时，失败记录允许空正文，客户端显示通用“生成失败”。这项例外限于已登记的AI失败结果。缺key等生成前置拒绝仍走提示事件。具体服务商错误和失败代码保存在生成诊断信息中，详细说明仅向触发者投递。

### 3. 展示、上下文和成功标记

消息历史、实时消息、搜索及热缓存携带一致的结果元数据。客户端以generation_id收尾草稿并显示失败标签，刷新后通过历史恢复。空失败正文与展示用提示分开存储。

模型上下文在热缓存和SQL两条读取路径都排除failed结果，旧缓存缺少元数据时兼容读取或回源。过滤后按原上下文条数与字符上限补足可用历史，避免大量失败记录挤掉正常上下文。失败历史落库确认不触发接话，也不置位冷场成功标记；结果投递确认与成功发言记账分别处理。

### 4. 控制通知与低频校验

复用现有C++到Python的gRPC事件流，新增房间/生成控制变更提示。控制事务提交后发送提示，携带目标和单调控制版本；接收方据此读取持久状态、取消上游并更新本地控制视图。旧事件和重复事件不直接覆盖本地较新状态。

对活动生成保留可配置的低频SQL校验，建议初值1秒，并在连接恢复和任务恢复时立即同步。通知丢失由校验补偿，数据库状态不可判定时停止当前上游调用并保留可恢复任务。控制请求的响应和界面确认依据持久化结果。

Python移除每100ms及每片段额外重复的控制SELECT，周期校验可批量读取。C++合并重复控制读取，只有版本失效和入群校验的正确性得到验证后才替换相关查询。成员和入群校验、结果提交前控制检查独立保留。分别测量Python和C++的读取次数及端到端停止耗时，不把快照写入量算成已减少的控制读取。

### 5. 搜索候选与字面复核

优先评估当前MySQL支持的ngram全文索引。索引只缩小候选集合，最终沿用LOCATE及既有房间、发送者、时间、seq游标条件，不把相关度排序引入现有接口。

V10使用ngram索引与独立空停用词表。实现先将优化范围限定为U+4E00至U+9FFF基本汉字组成的至少双字关键词，以完整词的短语匹配作为候选。运行时校验token_size为2和空停用词表。索引大小、分词粒度、停用词、大小写和排序规则需要在实际数据上核对。单字、特殊字符、空关键词、混合语言及不能证明完整召回的输入直接回退。新数据可见性和索引构建期间也须有准确路径，不能先截断候选再过滤导致分页漏项。

先用固定语料进行新旧查询逐项对照，再记录执行计划、耗时分布及索引空间。只有证明语义完整且有实际收益的输入形态启用优化。暂不引入外部搜索服务，以减少额外的一致性维护。

### 6. Redis补丁验证

在独立测试环境验证跨线程排队发送与连接断开的顺序，检查回调仅完成一次、结束连接及时失败、订阅与取消订阅处理、认证/数据库选择失败后的清理，以及重连后的合法命令。

增加固定版本的原版与补丁对照，必要时对应用、Drogon和hiredis一起启用内存检测。聊天室故障窗口同时覆盖登录、消息保存、跨实例推送和AI结果。依赖错误回调与正常超时分别计数，沿用日志字段白名单。

先验证已结束连接的发送边界，再调查历史登录超时和堆损坏。只有故障位置、时序和修复前后对照吻合时才得出同源结论。升级Drogon时检查上游等效修复并运行同一组回归，以决定补丁适用版本。

## Risks / Trade-offs

- 旧终态信息不足 → 使用legacy_unknown，保持已结束状态并核对旧消息，不推断失败原因或重启旧任务。
- 失败保存与控制并发 → 房间/生成锁、尝试及入群检查、事务终态与generation_id去重共同裁决。
- 控制提示丢失或乱序 → SQL为准，单调版本、低频校验与恢复同步补偿。
- 低频校验增大故障时控制等待 → 周期可配置，测量数据库超时和取消完成的总耗时，正常路径采用主动提示。
- ngram漏召回或无性能收益 → 原字面查询作为对照和准确回退，按验证后的输入范围启用。
- 原版偶发崩溃难复现 → 分别报告机制探针、压力测试、内存检测和完整故障结果，保持同源判断可追溯。

## Migration Plan

1. 新增扩展迁移，保存生成阶段、结束结果、最近非空快照来源以及消息结果元数据，按旧记录和已存消息证据回填。
2. 先完成兼容读取和原任务恢复，再协调升级C++、Python与前端；切换前暂停旧写入者，核对所有任务均采用统一状态转换。
3. 数据和恢复验证通过后收缩废弃的生成status/stopped表达。对外停止标记从统一结果派生，正式历史仍可读。
4. 单独创建搜索索引并验证候选完整性，未就绪时保留回退。观察控制与搜索基线后启用已验证的优化路径。
5. 回滚先关闭可选优化并使用准确查询及持久化控制路径。收缩前可回退兼容应用；收缩后需匹配的迁移恢复方案和备份，不能只换回旧应用。


## 设计更改对照表

| 原来 | 现在 | 用途/影响 |
| --- | --- | --- |
| 单个混合status及生成stopped标志 | phase与outcome分离，保留消息stopped兼容字段 | 处理进度和结束原因分别保存 |
| 失败清空快照并提示 | 最近非空尝试或空失败记录进入历史 | 刷新后保留结果，模型跳过failed |
| 每100ms按任务读取与片段重复SELECT | 控制提交提示、默认1秒批量校验及恢复同步 | SQL仍裁决控制，减少重复读取 |
| 所有关键词扫描 | 符合已验证词形时ngram候选加LOCATE，其余准确回退 | 保留字面、权限和分页语义 |
| 依赖内存问题缺少可复现入口 | 固定版本的本机独立断连及依赖内存检测探针 | 区分机制证明、压力与历史故障关联 |

表内为设计及本分支实现选择，实际验收以任务清单和可复现测试为准。
