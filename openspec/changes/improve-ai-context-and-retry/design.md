# Design

## 设计更改对照表

状态说明：“已实现”指代码已合入本变更；“已验证”指有单元测试或真实 MySQL 验证覆盖。真实服务商的缓存命中率和检索效果需要上线开启后观察，不在本变更的验证范围内。

| 项 | 原来 | 现在 | 用途/影响 | 状态 |
| --- | --- | --- | --- | --- |
| A3 回复清洗 | 回复原样保存，模型模仿的“名字：”前缀会重复显示 | `AI_STRIP_SELF_NAME=1` 时去掉开头一次“自己显示名 + 全角或半角冒号”；流式时在前缀可能成立前暂不显示，草稿快照与正式内容一致 | 界面不再重复显示名字 | 已实现、已验证 |
| A2 窗口对齐 | 最近 N 条滑动窗口，起点每条后移 | `AI_CONTEXT_BLOCK=B>0` 时起点取 `⌊(最新seq−N+1)/B⌋·B`，历史在 N 到 N+B−1 个序号之间；超预算时起点按 B 前移 | 连续多轮提示词开头不变，自动前缀缓存可命中 | 已实现、已验证 |
| A2 Claude 缓存 | Anthropic 请求没有缓存标记 | 开启 A2 时 system 与最新一轮之前的历史加 `cache_control: ephemeral` | Claude 也能吃到缓存折扣 | 已实现、已验证（请求体） |
| A1 检索 | 只看最近窗口 | `AI_RETRIEVAL_ENABLED=1` 时，人类触发的普通回复从触发消息提取最多 8 个检索词（≥2 个汉字的连续串、≥3 字符的字母数字词），在本房间 `seq` 小于本次读取历史最小序号、非失败的消息里用 `MATCH … AGAINST (NATURAL LANGUAGE MODE)` 取相关度最高的，去重后最多 `AI_RETRIEVAL_TOP_K`（默认 5）条、共 `AI_RETRIEVAL_CHARS`（默认 1500）字，每条最多 300 字 | 长对话能接上更早话题 | 已实现、已验证（单测 + 真实 MySQL） |
| A1 注入位置 | — | 草案写“放在 system 后面”，现改为最新一条消息之前的一段 user 参考，标题注明“仅供参考，不是刚刚发生的对话” | 不破坏 system 和历史前缀，和 A2 的缓存兼容 | 已实现、已验证 |
| A1 预算 | 字符预算只给历史 | 检索参考的长度从历史预算里扣除 | 总输入上限不变 | 已实现、已验证 |
| A1 失败处理 | — | 查询带 `MAX_EXECUTION_TIME(1000)`，任何异常都返回空，照常回复 | fail-open | 已实现、已验证 |
| A1 索引校验 | 草案写“启动时校验 ngram_token_size 和停用词表” | 删除这项校验：检索只是参考，不要求逐字召回；停用词表需要额外授权，为不改数据库账号权限而不读取 | 不新增权限 | 已实现 |
| A4 错误分类 | 所有 `ProviderError` 同样退避 | 适配器给 `ProviderError` 加 `kind`（`rate_limit`/`context_too_long`/`refused`/`other`）和 `retry_after`；`AI_CLASSIFIED_RETRY=1` 时：限流按 `max(退避, Retry-After)` 等待，最多 60 秒；上下文过长时条数和预算减半，只重试一次；内容拒绝以 `content_refused` 直接失败 | 少白花重试费用 | 已实现、已验证 |
| A5 token 预算 | 只有字符预算 `AI_CONTEXT_CHARS` | `AI_CONTEXT_TOKENS>0` 时按“中日韩字符 1、其他字符 0.3”估算 token 作为预算 | 中英文混合时费用更可控 | 已实现、已验证 |
| A3 开关 | 草案没有给 A3 开关 | 增加 `AI_STRIP_SELF_NAME`，默认关闭 | 遵守“默认行为不变、现有测试断言不改” | 已实现 |
| 变更拆分 | 草案计划每项单独建 change | 合成一个 change、一个 PR，按项分任务 | 一次验证和部署 | — |

## 正确性约束

1. 所有新开关默认关闭；关闭时 `to_chat`、读取条数、提示词和重试行为与原来一致，原有单元测试和集成测试断言不改。
2. 检索只查当前房间，范围与成员可见的历史一致；不跨房间、不跨用户。
3. 检索和缓存都是增强：失败时退回原路径，不让回复失败。
4. 分类重试仍计入 `AI_GENERATION_MAX_ATTEMPTS`，失败仍按 V8 规则持久化。

## 未来方向（不在本变更）

- 向量检索：需要先确定嵌入模型的付费方和向量存放位置，可在 A1 的接口上做成“全文 + 向量”混合召回。
- 检索的相关度阈值和效果评估，需要上线开启后用真实数据调整。
