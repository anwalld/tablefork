## 1. 当前实际行为

- watcher 当前顺序为：修改 HAProxy 后端 FQDN → 等待 FQDN 与实际 IP 都匹配新主 → shutdown sessions → 客户端重新建立 Redis 连接。没有在切换开始时先关闭业务入口。
- 等待实际 IP 更新期间，请求仍可能到达旧主；关闭连接时，正在执行的请求可能失败，也可能已经执行但客户端未收到结果。当前修复不能被描述为“切换期间请求无损排队，恢复后统一补发”。
- 后端已有按房间提交任务的 worker 队列（chat_socket.cc 的 roomWorkers().submit），但它不是等待 Redis 主从切换完成的专用请求缓冲。
- 前端 ChatSocket 已有内存 pending Map：断线后重连、重新订阅、重发未确认消息；可重试错误和 ACK 超时也会触发自动重试，保持原 client_msg_id。ChatView 保留发送状态，并提供失败后的手动重试。
- 当前 ACK 超时为 5 秒、MAX_ATTEMPTS 为 4。transmit 在 socket 未 OPEN、实际 write 返回 false 时也会递增 attempts；需要验证重试预算能否覆盖现有 30 秒恢复界限。此处是源码发现的待验证问题，不宣称已完成故障复现或修复。
- pending/outbox 位于页面内存，不能据此承诺刷新页面或关闭浏览器后恢复待发消息。
- 服务端保存消息时按 room_id、member_id、client_msg_id 查询已有记录，数据库也有对应唯一约束；ACK 在消息保存完成后发送。新方案应保持这一确认语义。

## 4. 服务端缓冲需要明确的设计边界

- 接收与执行：切换开始后如何阻止新业务访问旧主；从哪里得到切换状态；多个 C++ 实例如何一致执行。仅调整清连接顺序不等于已经有业务执行闸门。
- 存放位置：Redis 不可用时不能把“依赖 Redis 的队列”当作唯一保障。内存缓冲需明确进程重启会丢；要求重启后继续补发，则需要独立可用的持久化存储及恢复流程。
- 确认语义：仅进入临时内存队列不能发送现有“消息已保存”的 ACK。持久化接收确认若要新增，应与最终保存确认明确区分，不能让客户端提前删掉唯一待发副本。
- 有界性：每用户、房间及实例的容量和最长等待；满队列/超时应给出明确可重试失败，不能无限积压。
- 安全与权限：恢复后重新检查会话、成员资格、封禁及限流；排队期间被踢或退出登录的请求不能无条件执行。认证服务不可用时不能把尚未验证的身份当作已授权。
- 幂等与顺序：沿用 client_msg_id，处理“已提交但 ACK 丢失”；定义同一房间、同一用户及跨实例排队的顺序。取消、重连、重复提交和过期也要有明确规则。
- 失败责任：客户端与服务端可能同时重试，必须明确谁保留待发副本、何时停止重试，以及如何向用户展示最终结果。

以上均为下一轮待确定事项，不代表已经选定增加新的存储或队列组件。

### Explore 决定 14：用MySQL业务请求记录确认结果并去重（已确认）

用户提出“mysql里面有该房间啊 查了不就行了吗?”，在解释唯一请求编号、同事务保存对应关系及唯一约束后，用户回答：“可以 就这样”。

- 将调用者、操作、参数对应关系与业务结果关联；相同编号不能跨用户串结果，也不能用不同参数静默复用旧结果。
- 数据库业务写入及该请求编号到业务结果的记录放入同一MySQL事务，利用唯一约束处理并发；接手时查到已提交记录即返回原结果，不再重复写业务数据。
- 查不到记录不代表可以绕过并发控制直接执行；原事务可能还未提交，后续执行仍必须受唯一约束/事务保护。
- 正常直通和排队执行需要使用一致的业务请求编号与去重入口，覆盖切换恰好发生在请求中途的情况。
- 聊天消息复用已有(room_id, member_id, client_msg_id)去重语义；创建房间等接口需补请求与结果映射，不能按房间名猜测。
- 临时桶、任务状态和结果缓存仍按已选方案放独立Redis内存；MySQL记录的是业务提交与去重结果，不把整个临时请求桶改成持久化队列。
- 业务记录随业务资源删除后的处理、去重记录生命周期需设计，不能删掉资源就把旧请求当成从未执行。
- 登录/刷新会话等含Redis副作用的接口，以及外部副作用，不能假设一个MySQL事务包住所有系统；实现前逐接口核对可恢复结果和安全重试方式，缺少证据时保留结果未知，不盲重放。
- 通用去重记录不保存原始密码、API key或会话cookie等明文凭据，不将这些内容写日志。

当前只确认这一去重与结果恢复方向，不宣称现有所有接口已实现，也不宣称Redis领取锁或MySQL查询单独能实现全业务只执行一次。整体后端方案仍需完成接口与故障分支设计。

#### 自动停发的工程设计要求（需通过测试证明，不是现有能力）

- 采用有期限、有控制代次的运行许可；启动/重连默认无许可，经过当前协调者握手后才能执行。许可到期未续约时自动暂停业务执行与任务领取。
